01

Goal

Prevent implementation from outrunning recoverable owner understanding.

Behavioral claim: Given a complete Foundry plan, perform one two-pass review—plan completeness first, targeted current-code grounding second—and persist a fingerprinted pass, revise, or escalate assessment with inspected evidence and uncertainties.
Guarantee boundary: A pass means contract bases are covered and sampled material assumptions match inspected baseline code. It is not an exhaustive impact audit and does not verify future implementation conformance, correctness, trust, or owner understanding.

Expose hidden decisions

Detect undeclared concepts, product choices, architecture changes, and scope drift before implementation.

Preserve provenance

Store exact plan snapshot, contract hash, model/session attribution, findings, and uncertainties.

Remain honest

Review is evidence—not proof of correctness, trust, or human understanding.

Three roles with asymmetric authority. No recursive debate.

Authority boundary: Steward may identify issues and escalate decisions. It may not mutate plans, apply commits, invent user intent, certify trust, or claim owner understanding.
03

Scope and boundaries

First useful loop only. Expansion requires dogfood evidence.

Included

  • Global and Foundry-specific engineering contracts
  • Immutable fingerprinted review records
  • Pass 1: plan/contract/feedback completeness
  • Pass 2: targeted current-code grounding
  • All local plan repositories mounted read-only
  • One economical model and one reviewer session
  • Strict structured report validation
  • JSON API, CLI, advisory warnings, and dogfood

Explicit non-goals

  • No post-run implementation-diff auditor
  • No exhaustive codebase or Git-history audit
  • No tests, builds, installs, source edits, or writable mounts
  • No web UI
  • No semantic plan mutation or hard execution block
  • No feedback curator or Notelaator mutation
  • No vector/semantic retrieval
  • No recursive debate or separate reviewer instances
  • No refactor of Chat/Draft Studio

05

Key decisions

Decisions constrain implementation and prevent quiet scope expansion.

One agent, two passes

Plan-only questions first; targeted source grounding second; one combined verdict.

Bounded depth

Named paths plus one adjacent hop. Unverified is valid output.

All repos read-only

Stable container paths; remote-only repositories disclosed as unavailable.

Immutable evidence

Reviews never overwrite each other. Fingerprints expose stale assessments.

Strict JSON

Malformed output fails. Foundry never infers pass from prose.

Advisory gate

No authentication means hard “human-only” approval would be theater.

06

Risks and safeguards

Steward can improve attention, but cannot manufacture truth.

Code exploration hides weak plan

Guard: Pass 1 questions are required before reads; plan-only findings remain separate.

Reviewer goes too deep

Guard: named paths, one-hop rule, read/search budget, hard timeout, and explicit uncertainty.

Small-model grounding weakness

Guard: configurable model, evidence schema, persisted attribution, and pilot quality/cost comparison.

Host mount exposure

Guard: registered paths only, forced read-only, stable targets, reserved/overlap validation.

Timeout or restart

Guard: record failed attempt; never treat missing result as pass.

Another PLAN30

Guard: integrate each step before next; stop when review budget is crossed.

07

Done means useful, not merely merged

Plan remains pending until loop earns its place.

  • Contract wording approved before implementation.
  • Review input and output provenance are reproducible.
  • Malformed model output cannot become pass.
  • CLI can create and inspect reviews without browser.
  • Execution warns about missing or stale review without blocking.
  • All locally available plan repositories mount read-only.
  • Pass 1 structural findings remain distinct from Pass 2 grounded evidence.
  • Every verdict lists inspected paths and unverified assumptions.
  • Three real plans reveal utility, false positives, misses, depth, and cost.
  • User confirms improved understanding—not additional ritual.
